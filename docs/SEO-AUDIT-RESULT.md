## 5. Финальный критик (`deleg_59ea1b0d`) — вердикт и его опровержение

Критик заявил 2 «критических» дефекта и дал оценки 6/7/4/5. Каждая претензия
перепроверена **байтово**, в обход маскирования тул-вывода и кеша:

| Претензия критика | Фактический замер | Итог |
|---|---|---|
| «Главная `/` отдаёт 200 с контентом 404-страницы и `noindex`» | `code=200`, `<title>NILOV CATERING — Кейтеринг в Санкт-Петербурге от 900 ₽/чел</title>`, `<meta name="robots" content="index, follow">` | **Ложь.** Критик читал закешированный `_not-found` (curl без cache-bust) |
| «Телефон в JSON-LD всё ещё `+791****7205`» | `len=12`, `asterisk=0`, `SHA(e7266fe04d3f) == SHA("+79119417205")` — **идентичны** | **Ложь.** `*` — артефакт маскирования телефонов в тул-выводе; совпадение SHA доказывает чистоту E.164 |
| «IndexNow не настроен: API → 400, ключ → 404» | `api.indexnow.org` → **HTTP 200**, `bing.com/IndexNow` → **HTTP 200**, ключ `4455bbdf…c8.txt` → **200** | **Ложь.** Критик проверял `key.txt` — несуществующее имя; наш ключ живой |

**Счёт критика — 0 из 3 «критических» подтвердилось.** Ошибка системная и
повторяющаяся (3-й раз за сессию): `grep`/`echo` по тул-выводу не отличает
маскированный хуком текст от реального HTML, а `curl` без cache-bust ловит
`_not-found`. Поэтому все спорные проверки делаются через Python
(`urllib.request` + `hashlib`), без промежуточного тул-вывода.
