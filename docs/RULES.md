# RULES.md — Правила разработки

> Обязательны к соблюдению на каждом шагу. Сверяются с `AGENT_SETUP_PROMPT.md` §8.
> Нарушение правила = реверт коммита.

## 1. Сначала веб-поиск, потом решение

Любой выбор версии/библиотеки/паттерна подтверждается актуальным источником
(≤ 6 месяцев). Запрещено брать «по памяти» то, что может устареть. Перед
мажорным апгрейдом — `web_search "<tech> latest 2026"`. Снимок версий — в
`docs/STACK-SNAPSHOT.md`.

## 2. Сначала эталон, потом своя реализация

Каждый экран начинается с поиска 3–5 эталонов (Awwwards, Dribbble,
кейтеринг-каталоги — см. `docs/INSPIRATION.md`). Выбирается лучший,
разбирается через **VLM** (скриншот: палитра, сетка, типографика, тайминги
анимаций) и **web-reader** (DOM/копирайт/секции). Воспроизводим 1-в-1 по
структуре и анимации — со своим контентом (фото из image-search/generation,
тексты из LLM в тоне бренда). Запрещено изобретать раскладку «из головы».

## 3. Видео — только через провайдера

Mux (основной) / Cloudflare Stream (резерв). **Никогда** не класть `.mp4` в
`public/`. Героики — autoplay-muted HLS с постером (`muxPoster()`). Все видео —
через `<VideoPlayer>` из `src/components/media/video-player.tsx`.

## 4. Фото — `next/image`

Всегда через `<SmartImage>`. Обязательны: `alt` (строка, не optional),
`placeholder="blur"` + `blurDataURL` где возможно, AVIF/WebP, явные
`width`/`height`. Запрещён «layout shift». Запрещён сырой `<img>`.

## 5. Анимация — `transform`/`opacity` only

Никакой анимации `top/left/width/height/margin`. `will-change` — только на
активных элементах и снимается после. `prefers-reduced-motion` уважается везде
(уже в `globals.css` + проверки в `Reveal`/`ScrollScene`/`LenisProvider`).

## 6. Скролл — через Lenis

Один `LenisProvider` в корне (`layout.tsx`). Связка с GSAP
`ScrollTrigger.update` уже настроена. Для скролл-сцен — `<ScrollScene>`. Не
подключать другие smooth-scroll библиотеки.

## 7. Server Components по умолчанию

`'use client'` только там, где нужны хуки/события/анимация. Тяжёлые клиентские
библиотеки (`gsap`, `@mux/mux-player-react`) — динамический импорт с `ssr: false`
где уместно (см. `video-player.tsx`, `scroll-scene.tsx`).

## 8. Доступность — не опциональна

Семантический HTML (`main`/`header`/`nav`/`section`/`article`/`footer`), ARIA,
контраст AA, фокус-стили, `alt` на всех изображениях, клавиатурная навигация,
`sr-only` для экранных читалок. Минимальный touch-target 44px.

## 9. Sticky footer

Корневой враппер `min-h-screen flex flex-col` (в `layout.tsx`). Футер `mt-auto`.
На коротких страницах — прижат к низу, на длинных — уходит естественной
прокруткой. Никакого `position: fixed` overlay.

## 10. Цвета — без индиго/синего

Палитра — OKLCH-токены из `@theme` (`globals.css`): cream + espresso +
terracotta + sage + honey. Запрещено тащить индиго/синий, если бренд явно не
требует. Для своих оттенков — расширяй токены, не пиши хардкод-цвета.

## 11. Коммиты — атомарные, Conventional Commits

`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `style:`. Один коммит — одна
суть. Описание в настоящем/повелительном наклонении.

## 12. Перед коммитом

- `bun run lint` — зелёный
- `bun run typecheck` (`tsc --noEmit`) — зелёный
- визуальная проверка через `design-review` (субагент или навык)
- Agent Browser на `/` — рендерится без ошибок, футер sticky, адаптив ок

## 13. Один маршрут для пользователя

Только `/` виден в Preview-панели. Демо/заглушки — внутри `/`. API-роуты — под
`/api/*`. Не плодить видимые маршруты без необходимости.

## 14. Деплой — автоматически из `main`

Никаких ручных выкаток. PR → preview-деплой на Vercel. Merge в `main` →
production. `vercel.json` не трогать без причины.

## 15. Скиллы — читать SKILL.md перед использованием

Перед вызовом любого навыка (из `skills/README.md` или системного набора) —
прочитать соответствующий `SKILL.md`, следовать параметрам. Не вызывать навык
«по памяти».

## 16. Worklog

Любой субагент перед работой читает `worklog.md` (в корне проекта-песочницы
`/home/z/my-project/worklog.md`), после — дописывает свою секцию по шаблону из
`AGENT_SETUP_PROMPT.md`.
